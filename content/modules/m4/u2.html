Why this matters

Scenario opener

Sending a document as an attachment feels quick, but it also creates a copy you no longer control. If the work is still changing, or if the file contains sensitive data, that convenience can become a loss of visibility and control.

Core concept

A shared link gives access to a file you still control. An attachment hands over a copy that can live independently of you.

Neither method is always right or always wrong. The safer choice depends on whether the recipient needs a live version, whether they are inside your platform, and whether the file should be revocable after you send it.

When each tool fits

Use a shared link

Ongoing drafts, internal collaboration, named-person access, expiration dates, and revocation all point toward a link.

Use an attachment

Signed contracts, fixed records, and recipients outside your platform often need a file copy rather than a live link.

Common mistake

"Anyone with the link" is less restricted than it appears

A link can travel just as easily as an attachment if it is forwardable and not tied to named access. The phrase feels controlled, but in practice it often means "anyone who receives this from anyone else."

What to do

Default rule for everyday work

  • Default to named-access shared links for live work.
  • Use attachments when the file must stay fixed or the recipient cannot use your platform.
  • Use expiration dates, passwords, or named access when the content contains personal or sensitive data.

Exercise

Takeaway

Default to shared links with named access for ongoing work. Use attachments when the recipient needs a stable copy or cannot use your platform.
