Why this matters

Scenario opener

Many file problems do not start with an intentional overshare. They start because edit access was easier to grant than view access, a sensitive file inherited the wrong folder permissions, or an old contractor was never removed.

Core concept

Every shared file should answer three questions: who can open it, what can they do with it, and can they pass that access to someone else.

Safe permissions are not only about the first share. They are also about what happens afterward: inheritance, re-sharing, long-lived access, and permission drift over time.

What to review on any shared folder

  • Use the lowest access level that still supports the work: view before comment, comment before edit.
  • Check whether editors can share the file onward without asking you.
  • Check whether folder inheritance is wider than the file really needs.
  • Give temporary collaborators an end date, not open-ended access.
What to do

Permission cleanup as a habit

Reviewing a small number of high-value folders every few months catches most access drift. You do not need to audit every file. You need to revisit the places where sensitive or shared work accumulates.

Exercise

Takeaway

Grant the minimum access for the minimum time, and review what you already granted before it becomes invisible background risk.
